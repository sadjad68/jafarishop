## 6- کامنت گذاری کد ها

کامنت خوب برنامه نویس یا اعضای تیم بعدی کمک می‌کند. کامنت برای توضیح بدیهیات، نه برای توضیح منطق و ساختار کد استفاده می‌شود. ساختار کد باید خود توضیح دهنده باشد (Self-documenting). استفاده از کامنت برای `HTML` و `CSS` برای توضیح دادن اینکه چرا به این شکل نوشته شده است و چرا به کجاست به مربوط به کد بخش از کد است.

# ورک فریم (BootStrap)

یک مجموعه از کلاس‌های آماده برای چیدمان صفحات، دکمه‌ها، فرم‌ها، جدول‌ها و اجزای پرکاربرد رابط کاربری را در اختیار توسعه‌دهنده قرار می‌دهد و باعث می‌شود بدون نوشتن سی‌اس‌اس از ابتدا، صفحات استاندارد و متن‌باز سی‌اس‌اس است (فریم‌ورک بوت‌استراب یک چارچوب استاندارد و متن‌باز سی‌اس‌اس است که برای طراحی رابط کاربری منظم سریع و طراحی وب استفاده می‌شود. این چارچوب مجموعه‌ای از کلاس‌های آماده برای چیدمان صفحات، دکمه‌ها، فرم‌ها، جدول‌ها و اجزای پرکاربرد رابط کاربری را در اختیار توسعه‌دهنده قرار می‌دهد).

**برخی از ویژگی های بوت استریپ:**

* یک فریم‌ورک متن‌باز و رایگان برای طراحی رابط کاربری وب است.
* بر پایه CSS طراحی شده و استفاده از آن ساده و سریع است.
* دارای سیستم گرید (شبکه‌بندی) قدرتمند برای چیدمان صفحات.
* به‌صورت Mobile First طراحی شده و اولویت با نمایش در موبایل است.
* امکان ساخت صفحات کاملاً واکنش‌گرا (Responsive) بدون CSS زیاد.
* شامل کامپوننت‌های پرکاربرد مثل مودال، تب، آکاردئون و اسلایدر.
* سازگار با مرورگرهای مختلف.
* کاهش نیاز به نوشتن CSS از صفر.

# رسپانسیو چیست و چه نکاتی رعایت شوند:

طراحی سایت کردن یعنی نوشتن کد به گونه‌ای که صفحات وب در اندازه‌های مختلف صفحه نمایش، مثل موبایل، تبلت و دسکتاپ، به‌درستی نمایش داده شوند. در واقع هدف این است که بدون نیاز به نسخه‌های جداگانه، یک ساختار واحد با اندازه‌های مختلف تطبیق پیدا کند و تجربه کاربری مناسبی ارائه دهد.
شروع کردن از CSS معمولاً از دیدگاه کدنویسی انجام می‌شود و شامل چیدمان‌های منعطف، اندازه‌گیری نسبی و مدیا کوئری‌ها است. اگر از ابتدا با این دیدگاه کدنویسی انجام شود، صفحات وب منظم‌تر، قابل نگهداری‌تر و سازگارتر با دستگاه‌های مختلف خواهند بود.

## 1- مواردی که قبل از رسپانسیو کردن باید بهشون توجه کرد:

اگر HTML یا چیدمان صفحه اشتباه باشد، طراحی نشانه ی اغلب استایل‌ها نادرست استفاده‌ی نادرست از استایل‌ها اغلب نشانه‌ی طراحی اشتباه در ساختار صفحه است و به‌جای حل ریشه‌ای مشکل، فقط نتیجه را پنهان می‌کند. به همین دلیل، در پروژه‌های حرفه‌ای بهتر است این نوع استایل‌ها با دقت و فقط در شرایط خاص استفاده شوند تا کد تمیز، قابل پیش‌بینی و قابل توسعه باقی بماند.
اگر بدون آگاهی یا به‌صورت موقت استفاده شوند، استفاده از استایل‌های مخفی برای حل مشکل در واقع باعث ایجاد باگ‌های پنهان در پروژه می‌شود. این نوع استایل‌ها اگر بدون آگاهی یا به‌صورت موقت استفاده شوند، باعث می‌شود مشکل را حل می‌کنند اما در ظاهر مشکل را حل می‌کنند اما در واقع باعث ایجاد باگ‌های پنهان در پروژه می‌شود. این نوع استایل‌ها ریسپانسیو بودن سایت را از بین می‌برند و نگهداری پروژه را در آینده سخت می‌کنند.

## 2- چرا رسپانسیو کردن مهم؟

* بیشتر کاربران اینترنت با موبایل وارد سایت‌ها می‌شوند.
* تجربه کاربری در موبایل و تبلت به‌طور چشمگیری بهتر می‌شود.
* از اسکرول افقی و به‌هم‌ریختگی صفحه جلوگیری می‌شود.
* خوانایی متن‌ها در صفحه‌های کوچک حفظ می‌شود.
* دکمه‌ها و لینک‌ها راحت‌تر قابل کلیک می‌شوند.
* نرخ خروج کاربران (Bounce Rate) کاهش پیدا می‌کند.
* زمان حضور کاربر در سایت افزایش می‌یابد.
* گوگل طراحی ریسپانسیو را ترجیح می‌دهد.
* استاندارد اصلی طراحی وب مدرن محسوب می‌شود.

# خطاهای رایج که در ظاهر درست اما در پشت پرده کثیف و اشتباه کد

اگر کد HTML یا چیدمان صفحه اشتباه باشد، طراحی نشانه ی اغلب استایل‌ها نادرست استفاده‌ی نادرست از استایل‌ها اغلب نشانه‌ی طراحی اشتباه در ساختار صفحه است و به‌جای حل ریشه‌ای مشکل، فقط نتیجه را پنهان می‌کند. به همین دلیل، در پروژه‌های حرفه‌ای بهتر است این نوع استایل‌ها با دقت و فقط در شرایط خاص استفاده شوند تا کد تمیز، قابل پیش‌بینی و قابل توسعه باقی بماند.
اگر بدون آگاهی یا به‌صورت موقت استفاده شوند، استفاده از استایل‌های مخفی برای حل مشکل در واقع باعث ایجاد باگ‌های پنهان در پروژه می‌شود. این نوع استایل‌ها اگر بدون آگاهی یا به‌صورت موقت استفاده شوند، باعث می‌شود مشکل را حل می‌کنند اما در ظاهر مشکل را حل می‌کنند اما در واقع باعث ایجاد باگ‌های پنهان در پروژه می‌شود. این نوع استایل‌ها ریسپانسیو بودن سایت را از بین می‌برند و نگهداری پروژه را در آینده سخت می‌کنند.

## 1- چند استایل اشتباه که بهتره بجاشون جایگزین بیاریم:

1. **استفاده از `!important`:** استفاده از آن ترتیب طبیعی CSS را می‌شکند و نگهداری کد را سخت می‌کند.
2. **برای باکس‌های محتوایی `height: fixed(px)`:** وقتی محتوا تغییر کند، متن بیرون می‌زند یا مخفی می‌شود.
3. **برای لایه‌های اصلی `width: fixed(px)`:** باعث خراب شدن ریسپانسیو و ایجاد اسکرول افقی می‌شود.
4. **برای چیدمان کلی صفحه `position: absolute`:** چیدمان را شکننده و وابسته به اندازه صفحه می‌کند.
5. **پیچیده Layout برای ساخت `display: inline-block`:** کنترل flex و grid نسبت به آن سخت‌تر است.

# مواردی که باعث پایین اومدن سرعت سایت میشن؟

* استفاده از ساختار تمیز HTML و پرهیز از تگ‌های اضافی و تو در تو.
* تعیین `width` و `height` برای تصاویر جهت جلوگیری از پرش لایوت (CLS).
* مشخص کردن نوع دکمه با `type="button"` یا `type="submit"` برای جلوگیری از رفتار پیش‌فرض ناخواسته.
* استفاده نکردن از `inline-style` برای دکمه‌ها (باعث `re-render` و کد تکراری می‌شود).
* قابل کلیک بودن لینک بدون نیاز به JS (با `fallback` مناسب).
* خودداری از قرار دادن `JavaScript` سنگین روی رویداد `onclick` لینک‌ها.
* افزودن `rel="noopener noreferrer"` برای لینک‌های خارجی با `target="_blank"` جهت بهبود امنیت و عملکرد.
* پرهیز از لینک‌های خالی (`href="#"`) چون باعث رفتار اضافی و رندر بیهوده می‌شود.
* تصاویر بزرگ و بدون فشرده‌سازی باعث کند شدن شدید سایت می‌شوند.
* فرمت‌های مدرن مثل WebP و اندازه‌ی مناسب کمک زیادی می‌کنند.
* کاهش حجم CSS، HTML و JavaScript با حذف فاصله‌های غیرضروری باعث کاهش زمان بارگذاری می‌شود.
* فایل‌های CSS و JS در `<head>` می‌توانند رندر را متوقف کنند؛ بهتر است سبک‌ها بهینه و جاوا اسکریپت‌ها `defer` یا `async` شوند.
* بارگذاری تنبل (Lazy Loading) تصاویر و ویدیوها.
* برای منابع حیاتی مثل فونت‌ها یا CSS ضروری می‌توان پیش‌بارگذاری تعریف کرد تا زودتر لود شوند.
* فونت‌ها را فشرده، وزن‌های غیرضروری را حذف و از `font-display: swap` استفاده کن.

## 2- موارد مهمی که در جهت سرعت css باید رعایت شوند

* شادو `box-shadow`های سنگین و تکرارشونده.
* انیمیشن با `height` ،`width` ،`left` ،`top`.
* افکت‌هایی مثل `blur` و `glassmorphism` بسیار پرهزینه هستند و امتیاز PageSpeed را پایین می‌آورند.
* روی والدهای بزرگ `opacity`.
* تصاویر بک‌گراند بزرگ در CSS.
* سایه‌ها و افکت‌های لایه‌ای زیاد (z-index پیچیده).
* انیمیشن‌های دائمی یا طولانی (infinite animation).
* برای ارتفاع‌های بزرگ صفحه `vh`.

## 3- موارد مهمی که در جهت سرعت js باید رعایت شوند

* از JavaScript فقط در صورت نیاز استفاده می‌شود و از اضافه کردن اسکریپت‌های غیرضروری خودداری می‌گردد.
* فایل‌های JS با `defer` یا `async` لود می‌شوند تا مانع رندر اولیه صفحه نشوند.
* کد JavaScript تا حد امکان کم‌حجم و مینیمال نوشته می‌شود و از منطق اضافی پرهیز می‌گردد.
* از اجرای کد در لحظه Load صفحه جلوگیری می‌شود و پردازش‌ها به رویدادهای کاربر موکول می‌شوند.
* انتخاب عناصر DOM به‌صورت بهینه انجام می‌شود و از `querySelector`های تکراری پرهیز می‌گردد.
* نتایج انتخاب DOM در متغیر ذخیره می‌شوند تا از جستجوی مجدد جلوگیری شود.
* از Timerهای غیرضروری (`setTimeout`, `setInterval`) استفاده نمی‌شود چون باعث مصرف منابع می‌شوند.
* از استفاده بی‌رویه از `innerHTML` خودداری می‌شود چون باعث Reflow و Repaint می‌گردد.
* کدهای JavaScript بلااستفاده حذف می‌شوند و فایل نهایی سبک تحویل داده می‌شود.
* از اجرای کد در Loopهای سنگین روی DOM اجتناب می‌شود و منطق ساده‌سازی می‌گردد.
* برای اسکریپت‌های ثانویه استفاده می‌شود (مانند مودال‌ها یا اسلایدرها) Lazy Load.
